## G. Docx export for Steve (2026-09-02) — a real Quarto/environment bug, not a paper problem

Rendering `paper_draft_5service.qmd` to docx (`quarto render ... --to docx`) for Steve (who wants
Word, not qmd/html) surfaced a serious, silent bug in this Quarto install (1.9.37): **every
`.callout-*` div's content vanishes entirely in docx output** — not just unstyled, completely
absent from the document. Confirmed via a minimal 4-line isolated test file (both 3-colon and
4-colon fence syntax), so this is an environment/Quarto-version issue, not something specific to
this paper's markup. Verified by round-tripping the docx back through pandoc to plain text and
diffing word counts against the html version (~1,000-word gap) — don't trust a clean `quarto
render` exit code alone to mean the docx is complete; it renders with no warning either way.

**Fixed** by converting all 16 real callout divs (the other ~6 `:::`-fenced blocks in this file are
figure-panel divs, left alone) to plain blockquotes (`> **Label:** text`), which don't depend on
Quarto's callout Lua filter at all — guaranteed to survive in every pandoc output format. Script
used: a one-off Python pass (not saved to the repo, per the usual scratch-script convention),
converting `:::: {.callout-TYPE}\n...\n::::` blocks into `> **Type:** ...` with each line prefixed
`> `. Also found two more docx-specific gaps in the same pass: (1) the three `DT::datatable()`
tables degrade to a raw ASCII-table dump in docx (`tbl-cliffs-delta` was already plain `kable()`
and fine; `tbl-attribution-drivers` and `tbl-regional-intensity` switched to `kable()` too — also
fixed real stale data in the latter while in there, see below); (2) Quarto's docx writer doesn't
render YAML `title`/`subtitle`/`author` as visible body text the way html does — the document
opened with nothing on page 1. Fixed with a `{.content-visible when-format="docx"}` block (this
mechanism, unlike callouts, was confirmed working) holding a manual, `.unnumbered` title block, so
it doesn't duplicate or get numbered into the section sequence, and doesn't appear in html (which
already gets its title from the YAML normally).

**Also found in the same pass, unrelated to docx**: `tbl-regional-intensity` (World Bank Region
relative intensity, Annex) was hardcoded to 5 stale regions with **Latin America ranked above East
Asia & Pacific** — the real, current `hotspot_area_stats.csv` has all 7 regions with East Asia &
Pacific actually leading (1.20× vs Latin America's 1.11×). Recomputed and fixed.

**How to apply, if this file (or any future docx-targeted qmd in this project) needs edited
again**: don't reintroduce `.callout-*` divs for anything that must survive in docx — use the
blockquote convention above instead. Re-verify any docx render by round-tripping through pandoc
(`pandoc file.docx -t plain`) and checking word count against the html version, not just a clean
exit code.
