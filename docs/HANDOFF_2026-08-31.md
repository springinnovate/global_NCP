## New "recurring risk category" flagged in `docs/runbook.md`

GeoPackage's `fid` column is handled inconsistently across geopandas/pyogrio versions — can
silently become an unnamed row index instead of a normal column. This is the **second** independent
fid/grid_fid-class bug this project has hit (first was the 2026-07-08 LCC `grid_fid` mismatch).
`docs/runbook.md` now has a top-level warning section on this; `scripts/
merge_new_variable_into_change_calc.py` is the hardened pattern (raw `sqlite3`, never geopandas,
for any fid-keyed join) — reuse it, don't write fresh geopandas merge code for gpkg files.
